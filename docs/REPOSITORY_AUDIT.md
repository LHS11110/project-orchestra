# 저장소·민감 정보·요구사항 점검

점검일: 2026-10-10. 범위는 같은 작업 공간의 FE, BE, DB, Wall, Orchestra 다섯 저장소입니다. 현재 추적 파일과 Git에 추가될 미추적 파일, 로컬 Git의 모든 참조에서 접근 가능한 커밋 이력을 검사했습니다. 원격 GitHub를 새로 fetch하거나 배포 서비스를 재시작하지 않았습니다. 아래의 구현 상태는 로컬 소스 기준이며 모든 기능의 운영 환경 검증을 의미하지 않습니다.

## Git 제외 규칙

| 저장소 | 발견·수정한 내용 |
|---|---|
| FE | Python 캐시가 미추적 변경에 노출되어 제외. 환경 파일의 하이픈 백업 이름, 인증서·키 저장 형식, 로그·캐시 제외 보강 |
| BE | `tests/`, `test_*.py`, `*.txt`, `*.groovy`의 포괄 제외 제거. 테스트·설정·빌드 소스는 포함하고 캐시·생성물·자격 증명 제외 보강 |
| DB | `*.txt`의 포괄 제외 제거하여 동의어 등 설정 파일이 누락되지 않도록 수정. 키 저장 형식·로컬 환경·생성물 제외 보강 |
| Wall | 기존 Phoenix build/deps 제외 유지, 키 저장 형식·로컬 환경·생성물 제외 보강 |
| Orchestra | 실제 inventory, results, 인증서 제외 유지, 키 저장 형식·로컬 환경·생성물 제외 보강 |

환경 파일·개인 키·캐시가 제외되는지, `.env.example`, 검색 동의어 및 테스트 소스가 제외되지 않는지 `git check-ignore`로 확인했습니다. 이미 추적 중인 파일 중 제외 규칙에 걸리는 파일은 없습니다. `.gitignore`는 과거 커밋의 데이터나 소스 코드에 직접 삽입한 비밀을 제거하는 도구가 아닙니다.

## 민감 정보

Gitleaks 8.30.1의 공식 release를 checksum 검증 후 사용했으며 탐지 보고서는 값을 완전히 마스킹했습니다. Git에 추가 가능한 현재 파일에서 비밀 탐지 결과는 0건입니다. 실제 로컬 환경 파일의 PASSWORD/SECRET/TOKEN 값이 이 파일들에 포함되었는지도 별도로 대조했으며 일치는 없습니다. 이러한 검사로 탐지되지 않은 모든 유형의 비밀 부재까지 보증할 수는 없습니다.

로컬 `.env`와 개인 키에는 실행에 필요한 민감 정보가 존재하지만 Git 제외 대상입니다. 점검한 실제 `.env`들은 권한 `0600`입니다. 외부 C++/Elixir 라이브러리의 공개 시험 키·암호 시험 벡터는 프로젝트의 운영 자격 증명과 구분했습니다.

- BE 커밋 `cc3b5ce6`의 `README.md:90` 및 `spring/src/test/resources/application.properties:22`에는 고정 JWT 키 리터럴의 기록이 남아 있습니다. 현재 테스트 키는 명확한 시험 전용 값으로 교체했습니다. 이 키가 과거 운영에 사용되었는지는 확인할 수 없으므로 사용했다면 교체 및 기존 토큰 처리 정책 확인이 필요합니다. 이력 자체는 수정하지 않았습니다.
- DB README의 고정 비밀번호 예제는 사용자 생성 값 placeholder로 교체했습니다.
- DB의 과거 Compose 이력에서 나온 curl 인증 탐지 3건은 실제 비밀번호가 아닌 `$${ELASTIC_PASSWORD}` 참조입니다.
- FE와 Orchestra 이력에는 scanner 탐지가 없었습니다. Wall은 로컬 커밋이 없습니다. 다섯 저장소의 로컬 이력에 `.env`·개인 키 파일 경로는 없었습니다.

## 커밋과 실행 상태

다섯 저장소에 미커밋 변경이 있습니다. Wall은 추적 파일 0개, Orchestra는 기존 LICENSE만 추적된 상태였으며 새 구현 파일은 미추적입니다. 따라서 로컬 작업 파일의 구현과 GitHub에서 clone할 수 있는 상태는 같지 않습니다. 이 점검에서 commit/push를 수행하지 않았습니다.

컨테이너 조회 시 Phoenix broker, storage-broker, E5 worker가 실행 목록에 없고 ES는 기존 공식 이미지였습니다. 최신 소스가 실행 중인 서비스 전체에 반영되었다고 볼 수 없습니다. Orchestra의 실행 계획·입력 검증은 배포 실행 자체와 구분해야 합니다.

## 검증과 수정

FE 기존 테스트 43개가 통과했습니다. Spring 전체 시험을 실행하면서 TLS 전환 이전의 평문 HTTP 로그 시험 서버가 HTTPS 클라이언트와 만나 대기하는 문제와 외부 CA가 없는 context 시험을 발견했습니다. 로그 시험은 network 대신 transport mock을 사용하여 11개 배치의 종료 flush·중복 전송 방지를 검사하도록 수정하고, context/security 시험에서는 외부 C++ 및 Redis adapter를 mock으로 격리했습니다. 운영 TLS 설정은 완화하지 않았습니다. 임베딩 URL에는 기존 HTTPS 기본값을 annotation에도 지정하여 최소 시험 설정으로 bean 생성이 가능하도록 했습니다.

최종 Spring 전체 시험: 77개 통과, 2개 환경 조건으로 생략, 실패 0개입니다. 생략된 시험까지 검증되었다고 간주하지 않습니다.

Orchestra 기존 시험 33개 및 다섯 저장소의 최종 publishable 파일 비밀 스캔·`git diff --check`도 통과했습니다.
