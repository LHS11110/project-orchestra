# 캔버스 WebSocket 및 편집 차분 전송 — 2026-11-12

## 적용 범위와 경로

캔버스 연결 전 로그인·홈·프로필·탐색 API는 HTTPS → Nginx → Spring을 유지합니다.
캔버스 연결 이후 앱의 편집·관리·파일 작업은 기존 인증된 WSS 채널을 사용합니다.
외부 GitHub API·이미지·YouTube 요청은 사용자 지정에 따라 원래 경로를 유지합니다.
초기 접속과 다른 브랜치 캔버스의 접속 준비, JS/CSS/폰트 같은 정적 자산 로딩도 HTTPS입니다.

- 편집·채팅·실행: WSS → Nginx → 브로커 → C++ → 저장소/VM 관리자.
- 파일·봇·저장소 연결 정책·참가자 프로필·URL 미리보기·터미널 티켓: WSS → Nginx → 브로커 → 내부 Nginx → Spring의 기존 서비스.
- 터미널 입출력 자체는 기존 별도 WebSocket을 유지합니다.
- Spring 내부 수신 URI는 `/internal/canvas/socket` 하나이며 공개 Nginx 리스너에서는 404입니다. 내부 토큰을 상수 시간 비교하고, 사용자 ID/캔버스 ID/IP는 브로커의 인증된 연결에서 정합니다.
- 브로커에서 읽기·쓰기·실행 및 관리자 작업을 구분하고, Spring에서도 활성 사용자와 현재 캔버스/작업별 권한을 독립적으로 검사합니다. GitHub 작업별 정책은 Spring 서비스에서 추가 검사합니다.
- 브라우저에 열려 있는 캔버스에만 전송 어댑터를 설치합니다. 연결이 끊겼을 때 HTTP로 자동 우회하지 않습니다.

## 편집 차분

새 C++ 서버는 `edit_protocol: 2`를 초기/재동기화 스냅샷에 광고합니다.
지원 여부가 확인되지 않은 서버에는 기존 필드 패치 형식으로 전송합니다.

- 코드/텍스트: UTF-8 바이트 위치 `at`, 삭제 길이 `remove`, 삽입 문자열 `insert`, 기준 내용 식별값 `base`를 `text_edits`로 보냅니다. 불변 Automerge snapshot은 반복 전송하지 않고 새로운 CRDT changes만 보냅니다.
- 셀 소스/유형: `notebook_edits`로 대상 셀 ID와 수정분만 보냅니다.
- 셀 추가/삭제/순서: `notebook_structure`로 ID 순서, 새 셀, 삭제 ID만 보냅니다. 기존 셀 소스는 포함하지 않습니다.
- 실행 결과: `notebook_results`로 바뀐 결과 항목과 삭제 ID만 보냅니다.
- 기준 내용이 달라진 텍스트 수정은 `CANVAS_TEXT_CONFLICT`로 거부합니다. 클라이언트가 최신 스냅샷과 보류 중인 로컬 문서를 병합하고, 동일한 저장 순번과 새 요청 ID로 다시 보냅니다. 저장 성공 후 응답만 유실된 요청은 기존 ID/순번/내용을 그대로 재시도합니다.
- 다른 셀에서 발생한 편집·결과는 로컬 재조정 중에도 보존합니다.

브로드캐스트는 새 브라우저가 `delta_commits: true`로 요청하면 수정 객체의 중첩 필드 패치를 `canvas_commit.patches`로 전달합니다. 큰 문자열 변경은 동일한 UTF-8 문자열 차분을 사용합니다.
권한상 이미 볼 수 있던 객체에만 패치를 보내며, 새로 보게 된 객체는 전체 값을 보내고 더 이상 볼 수 없어진 객체는 제거합니다. 구형 SDK/브라우저에는 기존 전체 객체 형식을 유지합니다.
초기 접속·누락된 revision 복구 스냅샷·객체 최초 생성에는 전체 상태가 필요합니다.
C++의 검증/저장 및 C++ → 브로커의 canonical 결과에는 전체 수정 객체가 사용될 수 있습니다. 차분 전송 보장은 편집 요청과 협상된 브라우저 브로드캐스트에 해당합니다.

실측 직렬화 예시(압축 전): 20셀 노트북의 한 글자 수정에서 기존 `notebookCells` 패치 250,870바이트 → 셀 차분 operation 168바이트. 60KB 코드의 한 글자 삽입 자체는 65바이트입니다. 내용과 메타데이터에 따라 달라집니다.

## 파일 전송

- 96KiB 단위 청크로 업로드·다운로드합니다. JSON/base64와 기존 gzip WebSocket codec을 사용합니다.
- 선언 크기·필드·파일 유형 및 기존 서비스의 파일 형식을 검사합니다. 중복 청크는 저장 바이트와 같을 때만 허용합니다.
- 업로드는 사용자+캔버스에 묶이고, 중단/만료 시 임시 파일을 정리합니다. 활성 업로드 수를 제한합니다.
- 다운로드 중 변경된 파일은 version 검사로 거부합니다. 다른 캔버스의 링크 리소스는 그 캔버스 읽기 권한도 검사하며 봇에는 허용하지 않습니다.
- 캔버스 연결 변경 시 대기 요청을 취소하고, 서비스 요청은 클라이언트당 2개로 제한합니다. 브로커의 실행 작업과 파일 작업은 별도 동시성 예산을 사용합니다.
